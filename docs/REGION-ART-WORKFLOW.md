# 区划艺术底图工作流

本仓库的区划艺术图必须采用 **SVG-first** 流程。SVG 是图像生成的语义与构图依据，不是最终页面上的可见覆盖层。

## 固定顺序

1. **锁定项目轮廓**：从当前项目布局（例如 `balanced`）读取区划路径。不得先按真实行政图生成，再把成品拉伸进项目轮廓。
2. **映射真实地理**：将真实高程、山系、河湖、道路、县级聚落与候选地标映射进项目轮廓坐标系。
3. **绘制 SVG 语义示意图**：在精确区划形状内表达地势、水系、聚落层级和地标锚点。此 SVG 必须提交到仓库，作为可复现的生成依据。
4. **由 SVG 生成栅格艺术图**：以语义 SVG 为主要图像参考，生成厚涂手绘图。生成阶段不得改变外轮廓或主要河网关系。
5. **清理与精确遮罩**：删除定位框、十字线、引线、调试文字和其他施工标记；再套用与第 1 步相同的精确 mask。
6. **地标稀疏化**：一个相对独立区域最多保留一个地标。地标必须位于正确岸线、城区或地形关系中；最终图中不保留定位符号。
7. **页面接入**：完整页面只加载最终 PNG/WebP。语义 SVG 与 mask 作为仓库内生成资产保留，但不作为页面叠加层。

## 资产角色

| 资产 | 必须保留 | 页面可见 | 用途 |
|---|---:|---:|---|
| `*-semantic.svg` | 是 | 否 | 图像生成的地形、河流、聚落和地标语义依据 |
| `*-mask.svg` | 是 | 否 | 最终轮廓裁切与几何校验 |
| `manifest.json` | 是 | 否 | 真实坐标、项目坐标、地标和来源记录 |
| `*-art-final.webp` | 是 | 是 | 完整地图页面唯一加载的艺术资产 |
| `*-overlay.svg` | 否 | 否 | 禁止发布；施工定位层不得进入 `dist` |

## SVG 示意图最低要求

- 外轮廓必须直接来自项目当前区划路径。
- 山地继续使用简化山形；河流使用受区划 clipPath 限制的主干线网，不追求一比一复刻。水体应使用低饱和、低权重色彩，避免模型将河湖符号扩张为大面积开放水域。
- 聚落不得堆叠微型建筑图标，必须使用面积与颜色深度表达四级语义：都市、县城、乡村/农田、荒野底色。
- 都市与县城色块依据真实聚落锚点形成连续或紧凑区域；默认使用灰白深浅表达建成密度，不以红色暗示城市材质。乡村使用更浅的农田纹理过渡，荒野不着色。
- 同级聚落必须携带地域生成描述，例如江南水田县城、北方旱作县城、山谷带状乡镇；不能只用一套全国通用建筑造型。
- 候选地标先在 SVG 中校验岸线与城区关系，只用小尺寸、高对比标点表示精确位置；标点尺寸不得覆盖河岸两侧或改变岸线语义。地标名称和生成描述写入 manifest，不在 SVG 中写文字。
- SVG 可以包含调试分组，但调试分组不得合成到最终图；发布资产中不得存在独立定位 overlay。

## 每个区划的工作流清单

在 `artwork/workflows/<region>.json` 新增工作流清单，并执行：

```bash
python scripts/validate_region_art.py artwork/workflows/<region>.json
```

校验器会确认：阶段顺序、语义 SVG、mask、最终图片、页面 tile 引用、地标密度，以及禁止发布的定位层。

南昌是当前基准实现：`artwork/workflows/nanchang.json`。
